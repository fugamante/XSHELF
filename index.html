01

Predictable Command Flow

XSHELF constrains system output before it reaches a model and records enough evidence for operators to explain what happened.

Capture

Collect command output and reduce it inside the runtime boundary.

Budget

Apply explicit character and line limits before prompt assembly.

Validate

Check structured output against stable JSON contracts.

Replay

Quarantine failures and preserve telemetry for later inspection.

02

Operator Surfaces

The runtime exposes state, policy, tasks, and telemetry through commands that are meant to be read by both people and automation.

Runtime state

Inspect backend, budgets, logs, transport policy, and model configuration.

./bin/xshelf core --json

Task graph

Fan out objectives, run bounded workers, and emit parseable progress events.

./bin/xshelf task check --json

Policy

Make execution boundaries and unsafe command decisions explicit.

./bin/xshelf policy show --json

Telemetry

Validate logs, inspect traces, and spot schema or budget drift.

./bin/xshelf logs validate --fix=false

Built for automation boundaries.

XSHELF does not treat model output as a transcript to skim. It treats command execution, structured result validation, and failure evidence as runtime contracts.

Loose agent flow XSHELF flow
Unbounded context Budgeted capture
Text-first result Schema-first result
Failure is ambiguous Failure is quarantined
03

Install And Verify

Start with read-only inspection. Run backend execution only after readiness and health checks pass.

1

Inspect runtime

./bin/xshelf version
./bin/xshelf task check --json
./bin/xshelf core --json
2

Check health

./bin/xshelf llm check
./bin/xshelf doctor
./bin/xshelf health
3

Run safely

./bin/xshelf cxo git status
