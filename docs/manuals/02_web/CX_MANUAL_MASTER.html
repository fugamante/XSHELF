XSHELF

Manual (Master)

Last updated: 2026-05-26 · Focus: deterministic, observable, safe runtime

Intent. XSHELF is built for predictable LLM-assisted work under load: bounded context, schema-validated structured outputs, strict telemetry, and safe automation boundaries.

XSHELF is a runtime substrate, not a chat transcript. It captures relevant repository output, enforces budgets before that output reaches the model, makes structured results checkable, and records enough telemetry to explain what happened later.

Naming note. xshelf is the canonical CLI, xs is the short alias, and cx remains the supported compatibility alias.

Runtime architecture notes. Runtime behavior is Rust-canonical and actively modularized. src/app/mod.rs remains the orchestrator while command families have been extracted into focused modules (introspect, runtime_controls, agentcmds, logview, analytics, diagnostics, routing, prompting, optimize, doctor, schema_ops, settings_cmds, structured_cmds, task_cmds). Contract behavior remains deterministic and quarantine-backed.

Quickstart

Run these backend-safe commands to confirm routing, task readiness, and runtime state.

cd 
./bin/xshelf version
./bin/xshelf task check --json
./bin/xshelf core --json
./bin/xshelf diag --json --window 20

What to verify

  • execution_path is Rust when available.
  • log_file points to .codex/cxlogs/runs.jsonl.
  • budget_chars/budget_lines are explicit.
  • diffsum-staged returns JSON that parses with jq.
  • Clipping is visible via ./bin/xshelf trace when it occurs.

Installation / Prereqs
  • Required: bash

  • Required for default backend: codex CLI
  • Dev: cargo/rustc (build/run cxrs)
./bin/xshelf doctor

Optional: ollama (local backend).

Common workflows
  • Summarize staged diff (JSON): ./bin/xshelf diffsum-staged | jq .
  • Generate commit object (JSON): ./bin/xshelf commitjson | jq .
  • Fan out an objective: ./bin/xshelf task fanout "..." --from staged-diff
  • Run pending tasks: ./bin/xshelf task run-all --status pending
  • Optimize from history: ./bin/xshelf optimize 200

More workflows are covered in the sections below.

Troubleshooting
  • Unexpected fallback: run ./bin/xshelf where <cmd> and confirm execution_path via ./bin/xshelf version.
  • Schema command fails: inspect ./bin/xshelf quarantine list, then ./bin/xshelf replay <id>.
  • Budget clipping surprises: run ./bin/xshelf budget and ./bin/xshelf trace; reduce capture scope or raise budgets intentionally.
  • Strict log validation fails: legacy rows may predate the current telemetry contract; new runs should conform.
  • Backend confusion: run ./bin/xshelf llm show and verify the selected model when using Ollama.
./bin/xshelf logs validate --fix=false
./bin/xshelf trace

Start Here: Verify What You’re Running

Prefer Rust execution. If you are on Bash fallback, expect reduced guarantees.

cd 
./bin/xshelf version
./bin/xshelf diag
./bin/xshelf where version diffsum-staged task optimize

The Pipeline (Capture → Budget → Embed)

System output is constrained before it becomes prompt text.

raw system output
  -> internal native reduction
  -> mandatory budgeting (clip/chunk)
  -> embed into prompt

Budgets. Use CX_CONTEXT_BUDGET_CHARS, CX_CONTEXT_BUDGET_LINES, CX_CONTEXT_CLIP_MODE, CX_CONTEXT_CLIP_FOOTER.

./bin/xshelf budget
./bin/xshelf trace

Structured Outputs (Schemas/Quarantine/Replay)

Schema commands request JSON-only output, parse JSON, validate it, and quarantine failures.

./bin/xshelf schema list
./bin/xshelf commitjson | jq .
./bin/xshelf diffsum-staged | jq .
./bin/xshelf next git status | jq .
./bin/xshelf quarantine list
./bin/xshelf replay <id>

Safety Sandbox (Policy Engine)

Blocks destructive patterns and out-of-repo writes by default.

./bin/xshelf policy show
./bin/xshelf policy check "rm -rf ."

Task Graph (Fan-out/Run/Run-all)

Tasks are the unit of migration to parallel work: small, role-tagged, log-linked.

./bin/xshelf task fanout "Ship release notes improvements" --from staged-diff
./bin/xshelf task list --status pending
./bin/xshelf task run-all --status pending

Telemetry (Contract/Validation/Heuristics)

./bin/xshelf logs validate --fix=false
./bin/xshelf metrics 50
./bin/xshelf trace

Heuristics.

  • effective_input_tokens high: prompts too large or too variable.
  • cache trend down: stabilize prompt templates and capture scope.
  • clipping frequent: reduce capture scope or raise budgets intentionally.
  • schema failures spike: enforce deterministic mode and reduce ambiguity.
