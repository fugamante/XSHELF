01

Operator Pipeline

System output is constrained before it becomes model-visible context. Every stage has an inspectable command surface.

Capture

Collect repository output and reduce it before prompt assembly.

Budget

Clip or chunk context with explicit character and line limits.

Validate

Require structured JSON contracts and quarantine invalid results.

Telemetry

Append enough runtime evidence to explain the run later.

02

Capabilities

Core surfaces are grouped around operator decisions: what is active, what is safe, what can run, and what failed.

Runtime state

Inspect active backend, budgets, logs, transport policy, and model configuration.

./bin/xshelf core --json

Task graph

Fan out objectives, list pending work, run bounded workers, and emit progress events.

./bin/xshelf task run-all --status pending

Policy

Block unsafe execution paths and make override state explicit for automation.

./bin/xshelf policy show --json

Telemetry

Validate log contracts, inspect recent traces, and identify budget or schema drift.

./bin/xshelf logs validate --fix=false

Not a chat transcript.

XSHELF is a runtime substrate for predictable LLM-assisted work under load. It favors parseable contracts, replayable diagnostics, and conservative policy over free-form agent output.

Structured Outputs

Schema commands request JSON-only output, parse JSON, validate it, and quarantine failures.

./bin/xshelf schema list
./bin/xshelf commitjson | jq .
./bin/xshelf diffsum-staged | jq .
./bin/xshelf next git status | jq .
./bin/xshelf quarantine list
./bin/xshelf replay <id>

Safety Sandbox

Policy blocks destructive patterns and out-of-repo writes by default.

./bin/xshelf policy show
./bin/xshelf policy check "rm -rf ."

Task Graph

Tasks are the unit of migration to parallel work: small, role-tagged, and log-linked.

./bin/xshelf task fanout "Ship release notes improvements" --from staged-diff
./bin/xshelf task list --status pending
./bin/xshelf task run-all --status pending

Telemetry

./bin/xshelf logs validate --fix=false
./bin/xshelf metrics 50
./bin/xshelf trace
  • effective_input_tokens high: prompts are too large or too variable.
  • Cache trend down: stabilize prompt templates and capture scope.
  • Clipping frequent: reduce capture scope or raise budgets intentionally.
  • Schema failures spike: enforce deterministic mode and reduce ambiguity.

Self-Optimization

./bin/xshelf optimize 200
